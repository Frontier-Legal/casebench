# Casebench releases

| Release | Scope | Gate to start the next release |
|---|---|---|
| R0 internal | repo conventions from the first commit (versioning, releases, branch rules, quality gates, contributor docs) and public decision records with the repo's AGENTS.md; the case / task / reference / metric model ([architecture.md](architecture.md)); the plugin contract, conformance and scaffold per kind, so anyone adds a jurisdiction, a data provider, a model provider or a capture parser as a package; `qa` and `outcome` tasks with court references from the Türkiye adapter; citation integrity against folder, S3, HTTP API and MCP corpora; zero-code capture of model calls, tool calls and backend steps; the target contract (Python entry point, HTTP with a start command, or command); one real agent as the target, onboarded with no change to its code like any other; a terminal table and a JSON report, no HTML before R1 | extraction agreement is measured per field on the first adapter's corpus, and one real agent's known open question is measured with court-derived keys |
| R1 open-source alpha and cloud | public repo to [open-source.md](open-source.md) standards (Apache-2.0 core, `ee/` team server); the 3-line SDK (`cb.instrument`, `cb.run`, `cb.http`, `cb.score`) with extras for OpenAI-compatible, Anthropic, Gemini, LiteLLM, LangChain/LangGraph and LlamaIndex, each source passing recorded-fixture conformance ([integrations.md](integrations.md), [instrumentation.md](instrumentation.md)); `init`, `run` and `ui` as the whole command surface, plus the setup skill; pytest plugin; `demo`; the workbench in local, cloud and team mode with inbox, golden data with second approval, court drafts, try a question, answer review with judge overrule, compare, harness waterfall, report ([workbench.md](workbench.md)); `push`, `pull`, `invite`; lawyer spreadsheet import and spreadsheet review round-trip; `research`, `drafting`, `editing`, `extraction` tasks with criteria metrics; targets (http, openai_compatible, python, mcp, proxy, offline); corpus connectors (folder, S3); reference judge; integrity controls; dry run, resume, network allowlist; GitHub Action; the Türkiye adapter built into the core | 5 external users reach a first report without maintainer help, each connecting their own agent with no change to its loop, at least one with lawyer-authored cases, one team's lawyers reviewing a run in the cloud with no IT ticket and no engineer help, and the neutrality terms are published |
| R2 second jurisdiction and harness depth | the remaining library extras; judge agreement screen, OIDC for self-hosted SSO, multi-reviewer blind review; Langfuse and LangSmith trace import, counterfactual runs ([harness-eval.md](harness-eval.md)); one open-data jurisdiction adapter, adapter conformance suite, statute-version and appeal tests, compare, Langfuse, LangSmith and Inspect export, reproducible manifests; scheduled runs in the cloud | 3 passing adapters, 10 external teams with a completed run, one third-party reproduction, one external harness team using stage diagnostics |
| R3 production | push mode: production answers sampled into the review queue; citation-check API explored as its own product. Not a priority: Casebench is for the evaluation stage | decided on usage evidence from R2, not scheduled in advance |

No dates. Each release starts when the previous gate passes.
