# Casebench user stories: connect, generate, run

Tags: `@P0` first release (R1), `@P1` R2, `@P2` later. Scoring and reporting stories are in [stories-report.md](stories-report.md).

```gherkin
@P0
Feature: Connect a trusted corpus
  As an AI engineer at a legal AI vendor
  I want Casebench to read decisions from the store I already have
  So that tests come from my jurisdiction's law without copying my corpus

  Scenario: Connector validated on a sample
    Given a corpus connector of type "s3" pointing at my raw decision store
    When I run "casebench corpus check"
    Then Casebench lists, samples and fetches 200 decisions by id
    And it reports which required fields are present or missing
    And it copies nothing except the suite it later generates

  Scenario: The system under test cannot verify itself
    Given my target is my AI's chat endpoint
    When I set that same endpoint as the corpus connector
    Then Casebench refuses the config and says citation checks must read raw decisions

  Scenario: Corpus behind a licensed API
    Given a corpus of type "http" pointing at a licensed decision API, with my API key in the environment
    When I run "casebench corpus check"
    Then decisions are fetched by id and a citation is resolved through the API's search
    And every fetched decision is cached locally and never fetched twice
    And "casebench run --dry-run" states how many API calls the run needs

@P0
Feature: Answer keys written by the court
  As an AI engineer with no budget for lawyers
  I want the ruling, cited statutes and cited decisions extracted from each decision
  So that every test has a correct answer a judge wrote

  Scenario: Only agreed extractions become tests
    Given a connected corpus and a jurisdiction adapter
    When I run "casebench extract --sample 2000"
    Then two different models extract each field independently
    And a decision where they disagree on a field gets no test for that field
    And the output shows the agreement rate for each field

@P0
Feature: Generate a suite
  As an AI engineer
  I want tests generated by type from my corpus
  So that I measure outcome, statute, precedent and citation accuracy separately

  Scenario: Stratified suite
    Given extracted answer keys
    When I run "casebench generate --types outcome,statute,precedent --n 500 --stratify court"
    Then 500 tests are created, balanced across court levels
    And each test records its source decision id and answer key
    And the suite is frozen with an id and a content hash

@P0
Feature: Connect the AI under test
  As an engineer at a firm with an in-house GPT or Claude tool
  I want to connect my tool without changing its code
  So that Casebench tests it the way lawyers use it

  Scenario Outline: Check a target before a run
    Given a target config of type "<type>"
    When I run "casebench target check"
    Then one sample test is sent and the parsed answer and citations are shown

    Examples:
      | type              |
      | http              |
      | openai_compatible |
      | python            |
      | mcp               |
      | proxy             |
      | command           |

@P0
Feature: Know the cost first
  As an engineer paying per token
  I want an estimate before a run starts
  So that a benchmark never surprises my bill

  Scenario: Dry run
    Given a 500-test suite and a configured judge
    When I run "casebench run --dry-run"
    Then I see call counts and token estimates for the target and the judge
    And nothing is sent

@P0
Feature: No memorised answers
  As an AI engineer
  I want tests drawn only from decisions after the model's training cutoff
  So that a high score reflects reasoning, not recall

  Scenario: Date filter
    Given my target's model has a training cutoff of 2026-01-01
    When I generate with "--after 2026-01-01"
    Then only decisions dated after the cutoff are used
    And the report states the cutoff and how many tests it allowed

@P0
Feature: The target cannot read the answer
  As an engineer testing a tool that searches
  I want to choose research mode or reasoning mode
  So that finding the source decision is not scored as reasoning

  Scenario: Reasoning mode
    Given reasoning mode is selected
    When an answer cites the test's own source decision
    Then the test is marked "leaked" and left out of the reasoning score
    And the list of source ids is exported for the target to filter out

@P0
Feature: Resume an interrupted run
  As an engineer running a long suite
  I want a crashed run to continue where it stopped
  So that I never pay twice for the same test

  Scenario: Rerun after a crash
    Given a run stopped after 312 of 500 tests
    When I run the same command again
    Then the 312 stored results are kept and only 188 tests are sent

@P1
Feature: Test a closed tool with no API
  As a firm evaluating a vendor product
  I want to export questions and upload the answers
  So that I can test tools I cannot connect to

  Scenario: Offline answers
    Given a frozen suite
    When I run "casebench export --format csv"
    And I paste each question into the vendor tool and record its answers
    And I run "casebench import answers.csv"
    Then the answers are scored exactly as a connected run would be
```
